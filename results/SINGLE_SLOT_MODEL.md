# 单时隙共享容量最小模型

单位Gbit/s。每条候选边(g,s)设二元关联x、承载速率y，每条业务设服务速率r、最低保障缺口d。

- 每站 sum_s x_gs <= 1。
- 0 <= y_gs <= C_gs x_gs。
- 每星 sum_g y_gs <= Q_s。
- 每站 sum_k r_gk = sum_s y_gs。
- 0 <= r_gk <= demand_gk；d_gk >= minimum_gk-r_gk，d>=0。

不设置每星最多GS数，第一版仅依赖共享接收容量产生耦合。零服务合法，缺口由目标惩罚。无排队、切换、用户下行或端到端时延。

三种策略：独立关联按原输入链路速率排序（并列按卫星编号），之后固定可选关联，用加权缺口优先、吞吐量次优的分配器；联合吞吐量优先、加权缺口次优；联合加权缺口优先、吞吐量次优。两次MILP实现字典序，第一目标绝对容差1e-7 Gbit/s量级，要求求解器报告最优，时间上限60秒，未最优则报错而非混入比较。

QoS主指标为加权最低速率缺口除以加权最低速率总量，另记录有缺口业务比例与总吞吐量。缺口比例不是丢包率或时延违约率。

实验只取首日00/06/12/18 UTC四个系统选取时隙，不代表72小时全样本结果。使用已有10dB假设损耗下链路容量。每星1.5Gbps；每站两流，负载1时需求各0.6Gbps，最低保障0.5/0.3，权重4/1。负载统一乘0.5/1/1.5/2/3。收紧组保留各站最好的两条边，其余乘0.25，业务与原组完全相同。这是合成压力测试，不能解释为UEL。参数未校准，不用于真实性能声明。

固定吞吐量策略关联再求一次QoS分配，用其与自由关联QoS最优值比较，判断关联选择能否带来额外收益。仅关联不同不证明关联必要，因为可能存在多重最优解。所有网关均允许业务从地面骨干进入，是GS侧合成流量，不冒充已建立的区域用户路径模型。

手算例：A-S1=1.2,A-S2=1,B-S1=1.1,B-S2=0.4；两星容量均1。两站各两流0.4，最低均0.4，权重3/1。独立均选S1，总服务1、加权缺口0.6；联合A选S2、B选S1，总服务1.6、缺口0。
