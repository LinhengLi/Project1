# 异构卫星系统下行馈电链路动态干扰管理：研究方案讨论总结

> **文档性质**：研究选题讨论备忘录（非最终技术方案）  
> **整理日期**：2026 年 11 月 14 日  
> **核心参考论文**：Zijun Liu et al., *Time-Continuous Frequency Allocation for Feeder Links of Mega Constellations with Multi-Antenna Gateway Stations*, arXiv:2505.12429v1 (2025).  
> **当前目标**：以多系统共存干扰管理和 AI 加速为主线，暂不引入用户业务、QoS 需求或用户侧网络性能模型。

## 1. 研究背景与选题调整

现有参考论文以巨型 LEO 星座与多天线网关站（Multi-Antenna Gateway Stations，MAGS）组成的**下行馈电链路**（卫星 → 网关站）为场景，研究动态同频干扰与连续时间频率分配。论文通过物理层干扰建模、干扰图构建及图着色算法，降低活动馈电链路的链路失效率（Link Failure Rate，LF Rate）。

结合已有的真实轨道传播、网关站建模和电磁干扰计算工作，我们拟从该论文的**单星座系统内部干扰管理**扩展到 **Starlink、OneWeb 与 GSO 共同存在的异构卫星系统频谱共存场景**。师兄已有的下行干扰检测、态势感知及预测框架可以作为潜在的底层技术复用基础，但其业务链路与本文的下行馈电链路是否一致，还需在实现前核对。

需要明确：本阶段研究的是**多卫星系统（multi-system）干扰管理**，而非引入不同用户服务类别的“多业务（multi-service）QoS 管理”。

## 2. 当前已确定的研究边界

| 维度 | 当前方案 |
| --- | --- |
| 研究对象 | Starlink Gen1/Gen2、OneWeb，以及 GSO 系统 |
| 链路方向 | **下行馈电链路**：NGSO 卫星发射，Gateway 接收 |
| 工作频段 | 拟优先考察 Starlink 与 OneWeb 存在馈电下行频谱重叠的频段；具体许可、使用情况与保护规则待核实 |
| NGSO 干扰来源 | 星座内部、Starlink–OneWeb 跨星座同频干扰 |
| GSO 的基本角色 | **优先作为受保护系统**；需要时再单独分析 GSO 下行信号对 NGSO Gateway 的干扰 |
| 资源分配变量 | 各活动 NGSO 馈电链路的子信道／频率指派 |
| 核心技术 | 动态物理层干扰计算、干扰图／图着色、AI 加速 |
| **主要性能指标** | **馈电链路失效率（LF Rate）** |
| 重要辅助指标 | 算法执行时间／加速比、频率切换率（FSR） |
| 独立约束检验 | GSO 保护合规性（按最终选定频段适用规则验证） |
| 暂不开展 | 用户业务需求、QoS 业务分类、用户链路吞吐量、用户路由及业务调度 |

**建模原则**：优先构建可复现的物理层与干扰管理模型；对真实轨道数据、公开技术参数和人为简化的仿真假设明确区分，不将未确认的实际载荷或频段使用情况表述为事实。

## 3. 下行馈电链路系统模型

### 3.1 多系统活动链路集合

设时刻／时隙 $t$ 的活动馈电链路集合为：

$$
\mathcal W(t)=\mathcal W_{\mathrm{Starlink}}(t)\cup\mathcal W_{\mathrm{OneWeb}}(t).
$$

每个活动链路 $u\in\mathcal W(t)$ 对应一颗 NGSO 发射卫星及其服务网关站 $q_u$，分配的子信道记为 $c_u(t)\in\mathcal C_u$。其中 $\mathcal C_u$ 可以体现运营商各自的许可频谱与可用频段；不能默认所有链路拥有完全相同的可选子信道。

可沿用参考论文对多天线 Gateway、卫星可见性、天线离轴角和候选卫星选择的系统模型。原论文采用最大仰角选星作为一种固定选星规则，本研究起步阶段可作为 Baseline，而非必然的最终调度规则。

### 3.2 单链路干扰功率

可借鉴参考论文式（1），计算卫星 $s$ 的下行信号对目标网关站 $q_u$ 的干扰功率：

$$
I_{s\to u}(t)=
\frac{P_s^{\mathrm{tx}}(t)\,G_s\!\left(\theta_{s,u}^{\mathrm{tx}}(t)\right)\,G_{q_u}\!\left(\theta_{s,u}^{\mathrm{rx}}(t)\right)}{\left(4\pi d_{s,q_u}(t)/\lambda_s\right)^2}.
$$

其中：

- $P_s^{\mathrm{tx}}$：干扰卫星发射功率；
- $G_s, G_{q_u}$：卫星发射天线与目标网关站接收天线方向增益；
- $\theta^{\mathrm{tx}},\theta^{\mathrm{rx}}$：对应离轴角；
- $d_{s,q_u}$：传播距离；
- $\lambda_s$：载波波长。

**注意**：上述表达式沿用了原论文的理想化自由空间传播形式。推广到 Starlink–OneWeb 异构场景时，需核对双方实际或假定的天线方向图、发射功率、频率重叠、极化和其他必要链路预算因素；不同频率子信道之间并非总能简单视为“相同或完全不干扰”。

### 3.3 聚合干扰及 I/N

对目标活动馈电链路 $u$，在同频干扰近似下，将所有频率重叠的 NGSO 干扰源求和：

$$
\widetilde I_u(t)=\sum_{s\in\mathcal S^I_u(c_u,t)}I_{s\to u}(t).
$$

其中干扰源既可来自 Starlink，也可来自 OneWeb。聚合干扰噪声比为：

$$
\left(\frac IN\right)_u(t)=\frac{\widetilde I_u(t)}{kT_{n,u}B_u}.
$$

$k$ 为玻尔兹曼常数，$T_{n,u}$ 为目标接收系统噪声温度，$B_u$ 为接收子信道带宽。若考虑 GSO 下行信号对 NGSO Gateway 的影响，应另外将该方向干扰加入对应接收端的聚合干扰模型；**NGSO 对 GSO 的干扰则在 GSO 受保护地球站处计算**，不能与上述两个方向混为一谈。

## 4. 核心指标与优化问题

### 4.1 链路失效判定与 LF Rate

参照原论文，以聚合 $I/N$ 超过相应门限作为“干扰导致链路失效”的判据：

$$
\ell_u(t)=\mathbf 1\!\left\{\left(\frac IN\right)_u(t)>\eta_u\right\}.
$$

这里 $\eta_u$ 为链路 $u$ 在**统一线性量纲**下的 I/N 门限（若采用 dB 值，须先转换量纲或采用 dB 形式比较）。于是：

$$
\boxed{\operatorname{LFRate}(t)=\frac{1}{|\mathcal W(t)|}\sum_{u\in\mathcal W(t)}\ell_u(t)}.
$$

**定义解释**：LF Rate = 干扰超标的活动 NGSO 馈电链路数 / 活动 NGSO 馈电链路总数。它是基于保护门限的**干扰失效指标**，不等同于实际通信设备掉线率、端到端业务中断率或用户 QoS。

原论文采用的聚合 I/N 门限为 **−12.2 dB**；在扩展到其他工作频段、其他接收系统或跨系统保护情形时，**必须核实适用门限，不应机械照搬**。

建议同时报告 Starlink 与 OneWeb 各自的 LF Rate，避免只看全系统平均值而掩盖某个运营商被牺牲的情况。该分项仍属**系统干扰指标**，不意味着引入业务需求。

### 4.2 拟研究的总体优化目标

首先以多星座馈电链路失效率最小化为目标：

$$
\begin{aligned}
\min_{\mathbf c(t)}\quad & \operatorname{LFRate}(t)\\
\mathrm{s.t.}\quad
& c_u(t)\in\mathcal C_u,\quad \forall u\in\mathcal W(t),\\
& \text{GSO 保护约束（按适用规则与统计窗口构建）},\\
& \text{频率分配与连续时间运行约束。}
\end{aligned}
$$

频率切换率（FSR）可作为辅助评价指标，后续根据研究需要选择作为硬约束或软惩罚，而非立刻固定复杂的多目标权重。

**重要区分**：若选定频段适用 ITU Article 22 的 EPFD 保护规定，GSO 保护应按照相应的统计限值、参考天线与评估方法检验；不能把 EPFD 直接等同于单时隙的 NGSO Gateway I/N 判据。NGSO 馈电链路 LF Rate 与 GSO 保护违规情况应分开报告。

## 5. 图着色建模与算法基线

### 5.1 动态干扰图

可将活动 NGSO 馈电链路表示为顶点，显著同频干扰关系表示为边，子信道表示为颜色：

$$
G(t)=(V(t),E(t)),\qquad V(t)=\mathcal W(t).
$$

参考论文通过自适应干扰阈值构建边，将原始的**失效链路数最小化 P1** 转换为**着色冲突数最小化 P2**。该转换属于近似建模：减少冲突边数并不严格等价于最小化聚合 I/N 超标的链路数。跨系统聚合干扰增加后，尤其应保留物理层 I/N 的最终校验。

跨星座建模时，可把图的边划分为 Starlink 内部、OneWeb 内部和 Starlink–OneWeb 之间三类，必要时保留干扰功率权重。GSO 的统计保护要求则作为独立约束，**不必强行完全转换为普通成对着色边**。

### 5.2 GG：Generalized Global

原论文提出的 GG 算法以计算效率优先，在经典 Global 贪心着色基础上引入：

1. 对顶点度数加入高斯扰动，产生多种着色顺序；
2. 对无法无冲突着色的顶点，选择邻居中使用次数最少的颜色；
3. 按相反的度数顺序进行全局着色调整；
4. 多次独立优化并选择较优结果，支持并行执行。

原论文报告 GG 的理论复杂度为 $O(N_{\mathrm{GG}}(|V|+|E|))$（在其算法与计算假设下）。GG 是我们应当复现的**高效率基线**。

### 5.3 CTS：Clique-Based Tabu Search

原论文提出的 CTS 针对多天线网关站的图结构：同一 Gateway 选择的多颗卫星形成团或近似团，其链路之间有较强站内干扰。CTS 的关键步骤为：

1. 对每个网关站形成的团进行划分；
2. 为团内顶点分配不同子信道，优先消除站内强冲突；
3. 生成多个初始着色方案，筛选候选解；
4. 在同一团内交换两个顶点的颜色，利用禁忌搜索降低跨网关站冲突；
5. 以原始链路失效效果对候选方案进行最终选择。

原论文主要设置 $C=N_{\mathrm{at}}$。在异构系统中，如果各 Gateway 天线数不同、各系统持有不同的合法频谱或跨系统不能自由共享信道，这一设定与团内置换机制均需要修改，**不能默认直接适用**。

### 5.4 时间连续性、图分解及容量模块的取舍

- **TCFA-GG / TCFA-CTS**：继承上一时隙仍保持相同网关站关联的链路颜色，并根据冲突收益控制换频；可直接参考其频率切换率（FSR）定义。
- **CCD / GSCD**：论文分别使用连通分量分解，以及基于网关站地理位置的 K-means 聚类分解，以并行处理大型干扰图。跨系统分解时需留意删除跨区／跨运营商干扰边可能引起的近似误差。
- **VSU 空闲子信道利用**：属于原论文的容量增强模块。我们**暂不把容量最大化作为主目标**，可记录方法，但不作为首阶段必做内容。

## 6. 原论文主要结果：用作基线的量化参照

论文所列仿真场景采用约 **34,396 颗 Starlink Gen1/Gen2 卫星、115 个 MAGS**，下行载频 **20 GHz**、总带宽 **500 MHz**，仿真 2 小时、采样间隔 10 秒；相关结果不能视为我们多系统场景下的预期性能。

在 $N_{\mathrm{at}}=25$ 的表 II 实验中：

| 算法 | 平均 LF Rate | 论文报告执行时间 |
| --- | ---: | ---: |
| Random | 61.63% | 约 0 ms |
| Global | 6.14% | 2 ms |
| HEAD | 1.20% | 445 ms |
| Gurobi | 0.77% | $10^5$ ms |
| **GG** | **1.16%** | **6 ms** |
| **CTS** | **0.89%** | **20 ms** |

其他重要结果：

- 在连续时间频率分配实验中，**TCFA-CTS 在 FSR = 0.015（1.5%）时，LF Rate 低于 1.1%**；
- 网关站聚类分解 **GSCD** 在文中实验条件下可节省约 70% 计算时间；
- 空闲子信道利用 VSU 在 $N_{\mathrm{at}}=20$ 与 25 时分别提高约 **6%** 和 **17%** 的平均系统容量（作为附加结果，非本研究首阶段指标）。

**解释**：已有 GG/CTS 的效率已较高。AI 加速的价值不能仅以“原始优化为 NP-hard”作为充分依据；必须在同一硬件、同一输入规模和包含预处理的计时口径下，实际测量模型推理、物理层计算、构图及优化耗时。

## 7. 拟形成的研究创新（待实验验证）

### 创新方向 A：异构多系统下行馈电链路联合干扰模型

将参考论文的单星座建模扩展到 Starlink 与 OneWeb 跨星座共频干扰，叠加 GSO 作为受保护系统的保护约束。重点是物理建模与合法资源集合的统一处理，而非仅仅增加一组卫星轨道数据。

需要警惕：多星座共存、NGSO–GSO 保护和图着色均已有相关研究。**单纯加入 OneWeb/GSO 不是自动成立的算法创新**；创新仍须体现在新的复杂场景、求解机制与定量收益。

### 创新方向 B：AI 加速动态干扰计算／构图

利用星座运动的可预测性与相邻时隙的时空相关性，对强干扰链路候选集、动态干扰图边或干扰风险进行快速预测，减少重复几何与干扰计算。在预测后保留必要的精确计算与物理层校验，避免因漏掉强干扰而损害保护性能。

### 创新方向 C：AI 辅助复杂约束下的快速频率分配

如果实验发现主要瓶颈在 GG/CTS 或跨系统约束求解，可进一步探索 GNN、学习式初始化、局部重着色或预测热启动。**模型选择在完成耗时分析之后决定**，不先强行指定 GNN、Transformer 或 LLM。

### 多运营商协调的建模前提

第一版可以采用**全局信息可见的集中式联合优化**，作为理想协同基线；它不代表现实中 Starlink 与 OneWeb 已共享全部运营信息或同意由单一调度器控制。后续可研究有限信息共享或分布式协调的现实性，但不属于当前第一阶段必须完成的工作。

## 8. 实验与评价计划

1. **单系统复现**：先在 Starlink 下行馈电场景复现物理层干扰计算、LF Rate、GG、CTS、TCFA 与运行时间；核对与原论文场景不同造成的指标差异。
2. **双 NGSO 星座扩展**：加入 OneWeb 轨道与 Gateway，比较独立频率分配与理想联合分配，报告全系统及各星座 LF Rate。
3. **加入 GSO 保护**：针对所选频段明确 GSO 受保护链路、法规适用范围、统计保护评估与合规指标；在保持相同 LF Rate 定义的前提下比较受约束算法。
4. **性能剖析**：分别统计轨道传播／可见性、天线几何、干扰矩阵、图生成、GG/CTS 优化、保护约束验证的耗时与内存开销。
5. **AI 加速验证**：针对最显著瓶颈提出模型或混合算法，对比纯传统方法，评价 LF Rate、FSR、执行时间、加速比，以及 GSO 保护违例情况。

**关键对比基线**：Random、Global、GG、CTS、TCFA-GG、TCFA-CTS；必要时加入 Gurobi 小规模参考解。跨系统优化还应设置“独立优化／无协调”与“理想联合优化”的横向比较。

**评价优先级**：

- **主指标**：LF Rate，越低越好；
- **效率指标**：总执行时间、分阶段耗时、加速比，越低／越高越好；
- **动态指标**：FSR，越低通常意味着换频开销越小，但需同时保证 LF；
- **约束指标**：GSO 保护合规性，应首先满足，不宜用更低 LF 换取违规；
- **诊断性指标**：强干扰边召回率、物理层聚合 I/N 误差、各星座 LF Rate，用来定位近似计算与公平性问题。

## 9. 当前未决的核心问题

1. 最终选择哪个**真实重叠的馈电下行频段**？两系统在该频段的发射／接收参数和许可边界是什么？
2. Starlink 与 OneWeb 的 Gateway 如何布设？公开站址与仿真假设如何明确区分？
3. GSO 保护对象、对应的地球站／波束／卫星参数及 EPFD 等适用规则如何确定？
4. 单系统 GG/CTS 在我们的时间步长、真实轨道输入、不同系统参数下能否稳定复现？
5. 真正的高复杂度瓶颈在**干扰计算／构图**还是**频率分配求解**？AI 有无可验证的加速空间？
6. 当各运营商合法频谱集合不同或不可交换时，CTS 的团内置换性质如何扩展？

## 10. 暂定题目与研究定位

**暂定中文题目**：面向异构 NGSO–GSO 频谱共存的 AI 加速下行馈电链路动态干扰管理

**暂定英文题目**：*AI-Accelerated Dynamic Interference Management for Downlink Feeder Links under Heterogeneous NGSO–GSO Spectrum Coexistence*

**一句话研究目标**：在 Starlink–OneWeb 多星座共存且满足适用 GSO 保护约束的条件下，研究低复杂度、低 LF Rate、低频率切换率的动态下行馈电链路干扰管理方法，并通过实际运行时间和干扰保护效果证明 AI 加速的收益。

**研究边界再次确认**：当前**不引入用户业务需求、QoS 业务模型、用户侧网络吞吐量或路由调度**。主要通过活动馈电链路 **LF Rate** 评价干扰管理质量，结合 Execution Time、FSR 与 GSO 保护合规性进行实验验证。
