# 新方向专项调研：业务流量、用户链路、队列与QoS

日期：2026-11-19。状态：第一轮定向检索与阅读任务拆解，**不是全文综述，也不是已经选定的系统模型**。

## 为什么先调研

我们尚无业务到达、用户链路、排队与QoS建模的研究积累。上一版方案中的“两级队列、用户回传、期限内交付”等均降为候选假设，不能当作已经获得文献支持的选择。暂不据此扩展仿真、指定流量分布或选择AI算法。

本轮沿用TWC、TCOM、TCCN、TVT、JSAC、TGCN作为优先检索范围，补充直接涉及用户上行的其他期刊。主要检索2023–2026年；不为了凑齐六刊而降低相关性。本轮筛出6篇目标期刊论文与1篇范围外补充，未形成TCCN、TGCN的新增核心条目，不表示这些期刊没有相关工作。

检索词组合：satellite/LEO/feeder/user link + bursty traffic/stochastic arrival/uneven traffic/queue stability/delay bound/QoS/capacity allocation/on-board。优先依据IEEE、出版社和作者所在高校存档。检索引擎显示的抓取时间不作为出版日期；无法获取全文的条目不推断其参数。

## 核心阅读清单

### M01：多业务到达与排队，优先获取全文

**QoE-Aware Flexible Capacity Allocation Planning for Multi-Service Satellite Communication Systems**。Teweldebrhan Mezgebo Kebedew等；TVT，2025年在线（2026年卷期信息仍需出版社核对）；DOI：10.1109/TVT.2025.3599772。

- 证据：作者高校存档的摘要和书目；不是全文精读。
- 已确认：研究多业务、变化的流量需求和不同的分组到达分布；利用排队分析处理容量分配与排队体验要求，采用多智能体DDQN。存档提供作者版本入口。
- 要提取：每类业务的到达过程、包长、缓存上限；QoE与排队时延如何关联；阻塞与QoE违约如何分别定义；容量更新周期与包级仿真周期是否不同。
- 边界：容量规划不自动等于星上快时标决策；QoE也不能直接替换网络QoS。是否含突发相关性、实际流量数据和馈电物理模型均待全文确认。
- [高校存档及全文入口](https://orbilu.uni.lu/handle/10993/66239)。

### M02：突发过程与时延尾部

**Martingale Theory-Based Delay Bound Analysis for Multi-Hop Heterogeneous Satellite Networks**。TCOM，73(7):5198–5213，2025；在线2024-12-05；DOI：10.1109/TCOMM.2024.3511710。

- 证据：IEEE摘要与书目，未核对全文公式。
- 已确认：使用多跳串联队列描述卫星到地面的过程，以Markov过程处理间歇性、突发性到达和服务，分析时延及积压上界。
- 要提取：Markov状态与转移矩阵的来源；到达与服务独立性、平稳性条件；稳定性与时延违约概率的关系；界与仿真如何比较。
- 边界：论文使用Markov模型不证明我们的业务应采用该模型；多跳理论也不一定需要完整移植到当前馈电问题。
- [IEEE记录](https://ieeexplore.ieee.org/abstract/document/10778624)。

### M03：非均匀需求与用户链路资源分配

**Spatial–Temporal Resource Optimization for Uneven-Traffic LEO Satellite Systems: Beam Pattern Selection and User Scheduling**。Lei Lei等；JSAC，42(5):1279–1291，2024；DOI：10.1109/JSAC.2024.3383445。

- 证据：作者高校PDF的可检索摘要与引言片段；未完成系统模型、参数表逐项核对。
- 已确认：面向非均匀业务需求，联合波束图样、功率、用户关联和时隙调度，降低需求与传输数据的不匹配；区分帧尺度与时隙尺度。
- 要提取：需求究竟是每帧给定数据量还是连续随机到达；区域用户怎样生成；用户链路容量、同频干扰和服务时长怎样计算。
- 边界：空间负载不均衡不等于时间突发；供需缺口不等于时延QoS，不能从题名推断有队列。
- [作者高校PDF](https://orbilu.uni.lu/bitstream/10993/58970/1/JSAC_2023_Anyue.pdf)。

### M04：馈电与用户链路耦合

**Dependency-Elimination MADRL: Scalable On-Board Resource Allocation for Feeder- and User-Link Integrated Satellite Communications**。Qiaolin Ouyang等；TCOM，73(8):6673–6688，2025；DOI：10.1109/TCOMM.2025.3529212。对应旧清单R01，不重复计作新发现。

- 证据：IEEE摘要与书目；全文细节尚待核对。
- 已确认：同时涉及馈电和用户链路，处理链路间资源竞争、上下行数据流耦合，分配波束、功率和带宽。
- 要提取：每个方向的数据路径、队列位置、到达假设、上下行的因果关系；执行时可见状态、训练位置与计算量证据。
- 边界：题名有on-board，不足以证明在实际星载硬件达到计算时限；也不能据此宣称已解决GSO聚合EPFD保护。
- [IEEE记录](https://ieeexplore.ieee.org/document/10839405/)。

### M05：用户链路与载荷架构

**User-Centric Flexible Resource Management Framework for LEO Satellites With Fully Regenerative Payload**。Sovit Bhandari、Thang X. Vu、Symeon Chatzinotas；JSAC，42(5):1246–1261，2024；DOI：10.1109/JSAC.2024.3365883。

- 证据：作者高校存档摘要及公开版本入口；未全文精读。
- 已确认：以再生载荷为前提，研究用户地理需求下的带宽、功率和波束覆盖，包含多播、缓存和切换，以交付时间等评价。
- 要提取：透明/再生载荷假设；信道、用户分布、缓存及交付时间定义；地面与星上处理职责。
- 边界：缓存内容交付不能直接视作用户上行业务排队；不把论文假设当作Starlink已公开的真实内部架构。
- [高校存档](https://orbilu.uni.lu/handle/10993/62188)；[作者预印本](https://arxiv.org/abs/2312.11127)。

### M06：统计QoS的另一条建模路径

**Statistical Delay and Error-Rate Bounded QoS Provisioning for AoI-Driven 6G Satellite-Terrestrial Integrated Networks Using FBC**。TWC，23(10):15540–15554，2024；DOI：10.1109/TWC.2024.3430836。

- 证据：IEEE摘要与书目，未阅读全文。
- 已确认：在有限码长及HARQ-IR下研究AoI、统计时延和可靠性相关的QoS指标。
- 要提取：到达模型、QoS指数/概率定义、重传与时延的关系；指标是否适用于普通宽带业务。
- 边界：AoI面向信息新鲜度，不默认适合文件上传或一般突发宽带；有限码长与重传也不预先加入我们的模型。
- [IEEE记录](https://ieeexplore.ieee.org/abstract/document/10609803)。

### M07：用户上行与队列稳定性，六刊外补充

**Joint user scheduling and resource allocation scheme for low earth orbit satellite systems considering queue stability**。Yiwen Liu等；Journal of the Franklin Institute，363(6):108527，2026；DOI：10.1016/j.jfranklin.2026.108527。

- 证据：出版社摘要和公开系统模型片段；全文获取受限。
- 已确认：用户上行接入，用户带数据缓存，卫星通过馈电链路转发至网关；以随机到达、队列稳定性、QoS和功率约束研究波束赋形与调度，采用Lyapunov方法。
- 要提取：馈电是否被简化为无限容量/固定容量；SINR门限与队列时延分别怎样处理；可支持到达率范围及计算开销。
- 边界：队列稳定不自动给出逐包期限保证；系统图含馈电不代表优化了馈电干扰。
- [出版社记录](https://www.sciencedirect.com/science/article/pii/S0016003226001274)。

## 阅读产出必须回答的问题

每篇精读卡统一记录：

1. **业务**：应用与传输方向；到达单位是bit、packet还是session；空间分布、时间分布、包长和相关性；突发从哪里来。
2. **证据来源**：实测轨迹、公开数据、标准、其他论文或作者自设；参数出处、页码、公式号与引用链。没有出处就标为作者假设。
3. **用户链路**：方向、频段、关联、信道、干扰、速率映射、接入调度；馈电瓶颈有没有被忽略。
4. **队列**：位置、单位、缓存容量；时隙内到达/服务次序；未服务数据、切换、溢出和重传怎么处理。
5. **QoS**：起止边界；平均时延、分位数、违约概率、丢包、阻塞、速率、稳定性分别是什么；哪些有约束、哪些只是结果图。
6. **在线性**：观测状态、同步与通信、训练和推理位置、计算平台、运行时间；是否利用未来信息。
7. **迁移**：可以复用的公式与条件；不适用的假设；是否有代码/数据。不能只抄算法名称。

对每篇区分“书目核验 / 摘要筛选 / 模型章节核对 / 公式与参数复现 / 结果复现”，当前均未标记全文已读。第一轮未下载新PDF，原有已读状态不变。

## 建议执行顺序与完成条件

先M01、M03：学会区分包级到达与帧级需求，建立候选流量模型对照；再M02、M07：比较时延尾部与队列稳定性；再M04、M05：判断用户/馈电耦合和星上架构；M06作为统计QoS补充。顺序是本项目的阅读判断，不是论文结论。

完成第一批模型精读后才作选择：至少比较两类有出处的业务模型；明确一篇用户链路参考；给出QoS计算边界和指标出处；形成带页码、公式号和参数来源的对照表。若关键PDF仍未获取，保持待定，不用摘要补造模型。

调研不应先承诺一个论文数量或完成日期。以“能解释并复现候选模型，再说明选择理由”为阶段完成条件。目前没有证据表明任何一篇已同时覆盖区域突发、用户接入、星上在线决策与NGSO–GSO馈电保护，也不能因此宣称该组合无人研究。
